## 二、关键缺陷详述

### P0-1 · `npm test` 当前是红的

- 提交态（HEAD）`theme.css` 有 **207** 处 `!important`；`scripts/check-css.mjs` 的 `BASELINE_IMPORTANT` 已被改成 **212**（说明有人知道会到 212）；但**当前工作区实际 213**。
- 即：基线设成 212 后，又有未提交的改动新增了第 213 处 `!important`，护栏正确报错但**套件变红**。
- 直接推翻前序复盘"构建与测试均已通过"的说法。
- 复现：`npm test` → `✗ theme.css 中 !important 数量为 213，超过基线 212`。

### P0-2 · `check-palette-contrast.mjs` 是空操作（WCAG AA 护栏形同虚设）

- 脚本正则：`/body#\{mx\.\$bc\}\.(cn-\w+)\.(theme-...)/`，期望匹配 `body#{mx.$bc}.cn-xxx.theme-light`。
- 但 `src/color-schemes/bamboo-china-palettes.scss` 已被重构（未提交改动，文件头注释写明"不再依赖 mx.$bc 的平台作用域"），实际选择器为 `body.theme-light` / `body.theme-dark` / `body[class*="cn-"]` / `body.cn-moye.theme-light` ……
- 结果：`Parsed 0 palettes.` → `0 pairs, 0 below AA` → `exit 0`。**所有"意境配色全部通过 AA"的声明（含前序复盘）均无依据。**
- **次生缺陷（即使修好选择器也仍在）**：脚本的 `color-mix` 解析器只支持 `color-mix(in srgb, ...)` 与 `white` 关键字，而调色板里已用 `color-mix(in oklch, ...)`（≥8 处）。这些颜色会被判为 `null` 而跳过，审计仍大面积失效。

### P0-3 · `gen-accent-aa.mjs` 失效且具破坏性

- 同样用 `body#\{mx\.\$bc\}\.(cn-[\w-]+)\.theme-...` 去匹配，同样匹配不到重构后的文件 → `blocks` 为空，只生成默认绿的高对比强调色。
- 后果：
  1. **重跑脚本会静默删除** `accent-high-contrast.scss` 里全部 16 套意境覆盖（文件自身注释却写着"编辑配色后运行 `node scripts/gen-accent-aa.mjs` 重新生成"——按它的指引操作反而丢数据）。
  2. 意境高对比强调色已成为**无法从源码复现的手写冻结数据**。

### P0-4 · 完全没有 CI

- `.github/` 下无 `workflows/` 目录。测试套件从不被自动执行，正是 P0-1~P0-3 长期腐烂却无人察觉的根因。前序复盘把"补 CI 自动跑测试"列为 P3 且从未落地。

### P1-5 · `versions.json` 非法版本号

```json
{ "3.2.11": "1.11.6", "3.2.1.0": "1.11.0", "3.0.6": "1.8.0" }
```
- `"3.2.1.0"` 是四段、非合法 semver、也非本主题任何真实发布，**几乎肯定是笔误**（应为 `3.2.1` 或 `3.2.10`）。会让 Obsidian 的"版本→最低 App 版本"查找出错/被忽略。

### P1-6 · 无远程 + 大量未提交改动

- `git remote -v` 为空；17 个 `.scss` 与 `theme.css` 改动、`docs/`、` .codebuddy/` 均未提交。
- 对于依赖 GitHub + BRAT 分发的 Obsidian 社区主题，这等于**无法发布、且状态不可复现**。前序复盘声称的"已全部落地"与 `git status` 矛盾。

### P2-7 · 目录名与品牌不一致

- 工作目录仍是 `obsidian-cupertino-main`（源自上游 Cupertino 主题），但产品已更名为 `Bamboo China` / `obsidian-bamboo-china`。提交历史里有 `rebrand` / `rename identifiers` 两次提交，唯独**目录/检出路径没改**，对贡献者与社区主题上架（按仓库名识别）都易造成混淆。

### P2-8 · README 与代码不符（多列了一套配色）

- README "意境配色"表列了 **17** 套，首行是 `zhuyin`（朱印）。
- 实际 `bamboo-china-palettes.scss` 与 `accent-high-contrast.scss` 均**无 `cn-zhuyin`**（只 16 套意境 + 默认）。文档夸大了一套不存在的配色。

### P2-9 · 半吊子重构（平台作用域不一致）

- 调色板重构的目标是"平台无关、任何模式下切换即生效"（去掉 `mx.$bc`）。
- 但 `accent-high-contrast.scss` 的 16 套意境覆盖仍写成 `body.accent-high-contrast#{mx.$bc}.cn-xxx.theme-light`，**仍绑定 macOS/自适应关闭**。结果：非 macOS / 自适应开启时，开"高对比强调色"对意境配色不生效——重构只做了一半。

### P2-10 · `accent-high-contrast.scss` 存在重复冲突的默认块

- 第 12 行与第 222 行都是 `body.accent-high-contrast#{mx.$bc}.theme-light`，但数值不同（12 行 `rgb(46,132,59)` vs 222 行 `rgb(66,128,88)`）；第 18 行与 216 行同理。
- 后者覆盖前者 → **12/18 行的默认块是死代码**。同时说明该文件是"脚本生成段 + 手写段"混拼，生成器无法完整复现（手写段不会被重生成），进一步坐实 P0-3。

### P3-11 · 前序复盘文档已过时且具误导性

- `bamboo-china-review.md` 多处称基线 **207**、"构建与测试均已通过"、"对比度检查解析 17 套全部通过"。现状：代码基线 212、`npm test` 失败、对比度检查 0 采样。**该文档应标注为历史稿或立即更新**，否则会误导后续维护者。

### P3-12 · `gen-accent-aa.mjs` 硬编码默认背景

- 默认深浅背景写死 `[255,255,255]` / `[20,20,20]`，未读取 `root.scss` 真实的 `--background-primary`（Bamboo China 深色画布实为 `color-mix`，并非 `[20,20,20]`）。默认高对比绿（`rgb(72,196,90)`）的 AA 计算基于错误底色，精度存疑。
